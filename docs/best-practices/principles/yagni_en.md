# YAGNI Principle

## Overview

YAGNI (You Aren't Gonna Need It) advises not implementing features until they're actually needed. From Extreme Programming (XP), it prevents over-engineering.

Build only what's required now; avoid speculative features. Benefits: Faster development, less wasted effort, simpler codebases.

## When to Use

During planning or coding—resist adding "future-proofing" features; ideal for agile projects.

## How to Implement

Focus on current requirements (e.g., don't add user profiles if only login is needed). Refactor later if needed. Think, "Do I need this today?"—like not buying extras you might never use.

