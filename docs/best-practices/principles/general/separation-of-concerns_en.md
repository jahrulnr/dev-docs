# Separation of Concerns
## Overview

Separation of Concerns divides a system into distinct sections, each addressing a separate concern, improving modularity and maintainability. This principle helps in creating systems that are easier to understand, test, and modify by keeping related functionality together and unrelated functionality apart.

## When to use
Apply across architecture and code (layers, modules) to avoid mixing responsibilities.

## Example
Split presentation, business logic, and data access into separate layers.

## Pros / Cons
- Pros: Easier reasoning, testing, and independent evolution.
- Cons: Over-abstraction can add indirection if taken to extreme.
